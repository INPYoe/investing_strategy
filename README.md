# 드러켄밀러 매수 후보 및 진입 시점 연구

전략 보강 연구의 재실행 방법과 완료/미완료 범위는 [검증 프로토콜](VALIDATION_PROTOCOL.md)을 참고한다. 1차 기준선 결과는 `reports/2026-09-22/validation/report.md`이며 실투자 우위가 검증됐다는 의미가 아니다.

> 2026-09-22 운영 추가: [분기 운영 문서](QUARTERLY_OPERATIONS.md)에 연구 전용 cron 예시와 기본 비활성 주문 어댑터를 설명했다. 실제 crontab은 변경하지 않았고 실주문도 하지 않았다. 최신 설계는 고정 3% 기준이 아닌 개별 확신·공동 방향과 위험균형 배분이며, 아래 3%/5% 설명은 과거 규칙이다. 자동 배분·실시간 사전 점검·체결 대사가 아직 미완성이므로 무인 실거래 완성본으로 사용하면 안 된다.

> 최신 요청 반영: 다중 중기투자 구루 전략으로 범위를 확장 중이다. 아래 기존 단일 구루·5% 연구 결과는 이전 규칙의 결과이며 신규 전략의 성과가 아니다. 최신 규칙은 `multi_guru_policy.json`, 구현은 `signal_rules.py`에 있다. 신규 최소 비중 3%, 비중과 분할 조정 수량 동시 확대·축소 확인, 평균 매입가 -20%는 알림·재검토로 확정했다. 수집기와의 통합 및 다중 구루 선정은 진행 전이므로 기존 후보 기반 주문안 생성은 차단했다. 종목 손실 20%와 계좌 내 종목 투자비중 20%는 서로 다른 개념이다. Mac mini와 상시 연결 SSD를 운영 환경으로 지정했다. 실주문은 활성화하지 않았다.

사용자 기준: 공개 주식 포트폴리오에서 보유 비중 5% 이상인 종목을 매수계획의 검토 후보로 등록한다. 주식·ADR·ETF 현물 합계를 분모로 하며 옵션과 원금 표시 채권은 제외한다. 본인 자산의 5%를 투자하라는 의미가 아니다.

현재 구현은 실제 데이터를 수집하는 재현 가능한 연구·공시 감시 프로그램이다. 공시 감시는 정기 실행하지만 자동 주문, 청산, 환전, 이메일 발송은 실행하지 않는다. 기존 자동주문 작업 중단과 기존 보유종목 매도는 서로 다른 상태다.

## 실행

프로젝트 상위 폴더의 기존 가상환경에서:

```sh
.venv/bin/python -m pip install -r guru_tracker/requirements.txt
.venv/bin/python guru_tracker/study.py --asof 2026-09-21
.venv/bin/python -m guru_tracker.portfolio_study --asof 2026-09-21
.venv/bin/python -m guru_tracker.automation status
.venv/bin/python -m guru_tracker.automation poll
.venv/bin/python -m pytest guru_tracker/tests -q
```

선택 환경변수 `SEC_USER_AGENT`에는 SEC 요청 식별용 프로그램명과 실제 연락처를 설정할 수 있다. 인증키가 아니다. 환경변수나 이메일 비밀번호는 출력하지 않는다.

## 데이터

- SEC submissions: 원본 공시 번호, 보유 기준일, 제출일, 접수 시각.
- 13f.info 공개 보유표: 현물·옵션 분리 및 과거 각 분기 후보 구성. 이번 연구의 명시적 대체 소스이며 제공자 단위를 보존한다.
- Yahoo chart: USD 일별 OHLC와 배당·분할 조정 종가. 공개 데이터의 이용 조건과 제한은 제공자를 따른다.
- 원자료와 URL·수집 시각은 `data/cache/`에 저장한다. 동일 URL을 재사용하고 제출 목록은 새로 확인한다.

이번 스크립트는 SEC 원문 정규화 수집기 전체를 구현한 제품이 아니다. SEC 원문 표 대조와 기업행동·과거 식별자 검증이 필요한 탐색 연구이다. 제출 목록과 원문 다운로드 가능 여부를 기록하며, 실제 연구 보유표는 13f.info로 통일한다.

최신 후보는 가장 최근 요청 공시에 해당하는 자료만 사용한다. 최신 자료 수집이 실패해도 과거 후보를 최신으로 대체하지 않는다. 원문 단위가 의심되면 전체 AUM을 임의 보정하지 않으며 상대 비중과 제공자 원시 값만 출력한다.

`ticker_overrides.json`은 CUSIP 기준으로 제공자의 잘못된 티커를 정정하고 근거를 보존한다. YPF를 Repsol로 연결한 오류와 Teck의 CAD 상장 매핑을 정정했다. `price_identities.csv`로 실제 가격 제공자의 회사명·통화·거래소를 검토할 수 있다. USD 외 가격은 환산 없이 섞지 않고 거부한다.

## 비교 설계

최근 20개 분기의 당시 5% 이상 현물 종목을 대상으로 6가지 진입 시점을 비교한다. 공시 현지 날짜 다음 거래일 시가를 기준 진입일로 고정한다. 공시 전 가격을 매수가로 사용하지 않는다.

1. 다음 거래일 시가.
2. 기준 진입일에서 5거래일 대기.
3. 10거래일 대기.
4. 20거래일 대기.
5. 기준일·5일·20일에 초기자금 1/3씩 분할.
6. 20거래일 내 기준 시가 대비 종가 -5%를 확인한 다음 시가. 미충족이면 현금 유지.

모든 방식은 기준 진입일에서 63/126/252/378거래일 뒤 동일 종가에 종료한다. 배당·분할 조정 가격, 편도 10bp 비용, 현금 이자 0을 적용한다. 미래 기간이 아직 끝나지 않은 사건과 가격 누락은 제외 사유를 남긴다. 해당 분기 후보를 동일가중 평균한 뒤 분기별 동일가중 평균한다. SPY 동일 기간 보유도 비교한다.

이는 겹치는 가상 사건들의 비교이며 하나의 계좌 수익률, CAGR 또는 구루의 실제 운용 수익률이 아니다. 후속 공시 매도 반영과 자본 제약은 아래 별도 포트폴리오 연구에서 다룬다. 세금과 원화 환산은 미구현이다. 분기별 재표본추출 구간은 사건·분기 중첩을 완전히 통제하지 못하므로 탐색적 불확실성 표시로만 사용한다. early/later 구분은 사후 탐색이며 최적 타이밍을 확정하지 않는다.

단위 테스트의 인공 가격은 계산 검증에만 쓰인다. 실제 리포트 데이터로 주입하지 않는다.

## 고정 자본 포트폴리오 연구

`portfolio_study.py`는 초기 USD 10,000을 공시 접수 다음 거래일 시가에 리밸런싱한다. 최신 후보를 과거로 소급하지 않는다. 기본은 앞서 수집한 실제 캐시만 사용한다. 처음 설치한 경우 `study.py` 실행 또는 `portfolio_study --asof YYYY-MM-DD --online`으로 실제 원자료를 수집한다. 누락 가격·비연속 공시·정정 공시 미해결은 실패 처리한다.

- 배분: 동일가중 35% 상한, 구루 상대비중 35% 상한, 구루 상대비중 상한 없음.
- 제외: 공개 비중 5% 미만, 3% 미만, 공개 현물 보유표에서 사라짐. 신규 진입은 모두 5% 이상이다.
- 편도 비용 10bp/30bp, 현금 목표 최소 2%, 소수 조정 단위, 레버리지 없음. 상한 초과분은 현금으로 유지한다.
- 전체 연속 운용과 early/later 각각 초기화한 연구를 제공한다. 분할 기준은 공시 보유 기준일 2024-01-01이며 사후 탐색이다.
- 산출물: `reports/YYYY-MM-DD/portfolio/`의 `research.md`, `comparison.csv`, `equity_curves.csv`, `paper_trades.csv`, `filings_holdings.csv`, `metadata.json`, `source_attempts.json`.
- 실패 실행은 metadata의 `status=FAILED`로 판별한다. 이전 성공 산출물이 남아 있어도 최신 성공 결과로 오인하면 안 된다.

현재 모의운용 기본안은 **동일가중·35% 상한·공개 비중 5% 미만 제외**다. 더 높은 과거 수익률을 보인 규칙도 있으나 미래 우위를 확정하지 않는다. 35%는 리밸런싱 목표로, 보유 중 가격 변동으로 초과할 수 있다. 실제 최대낙폭은 약 35%였으며 그 이상 손실도 가능하다. 자세한 판단은 `reports/2026-09-21/portfolio/decision_memo.md`에 기록했다.

## 공시 감시와 계좌 조회

`automation.py`의 `poll`은 SEC의 접수 시각을 확인하고 CUSIP 기준으로 중복 공시를 방지한다. 첫 실행은 기존 공시를 기준선으로 저장할 뿐 매수 신호로 만들지 않는다. 5% 후보와 직전 공시 대비 후보 편입·제외 및 비중 변화도 저장한다. 비중 변화만으로 실제 매수·매도 수량을 단정하지 않는다. 정정 공시는 별도 검토 대상으로 차단한다. 수집 실패한 공시는 처리 완료로 기록하지 않는다.

감시 자료는 `data/automation/latest_disclosure.json`, `source_attempts.json`, `ledger.sqlite3`에 저장한다. SQLite는 로컬 단일 호스트 WAL과 FULL 동기화를 사용한다. 외장 볼륨에서 rollback journal의 `SQLITE_READONLY_DBMOVED` 오류를 확인해 변경했으며, 네트워크 공유에서는 사용하지 않는다. DB를 옮길 때는 프로세스를 종료하고 WAL을 포함해 안전하게 백업해야 한다. [SQLite WAL 문서](https://www.sqlite.org/wal.html).

2026-09-21에 Codex 공시 감시 자동화 `드러켄밀러 공시 변경 감시`를 등록했다. 한국 시각 매일 07:17, 19:17에 확인하도록 설정했다. 의미 있는 공시·오류 변경만 알리며 거래는 하지 않는다. 정확한 시간의 체결을 보장하는 서비스가 아니며, 앱 실행 환경·네트워크·외장 SSD 접근에 의존한다.

`broker-check`는 한국투자 해외계좌 잔고·미체결·시세를 **조회만** 한다. `preview`는 최신 5분 이내 조회 결과로 수량 초안만 작성한다. 주문 가격 검증 또는 전량 매도 후 잔고를 가정한 실행기가 아니다. 현재 사용 가능한 USD와 보유 평가액으로 예산을 계산하며 아직 매도하지 않은 국내주식이나 예상 환전액을 주문 가능 자금에 더하지 않는다. 모든 산출물은 `orders_sent=false`다.

사용자가 지정한 계좌 전체를 예산 범위로 반영했지만 2% 운영 현금과 종목 상한 때문에 항상 100% 투자하는 것은 아니다. 신규 입금은 다음 조회에서 반영된다. 계좌 관련 비밀값은 환경변수 또는 별도 `.env`에서 읽으며 보고서에 기록하지 않는다.

## 실제 거래와 분리

기존 7개 자동주문 관련 작업의 중단 기록은 `data/automation/legacy_stop.json`에 있다. 이 중에는 기존 위험 점검 작업도 포함되므로 보유종목 보호가 계속 작동한다고 가정하면 안 된다. 계좌 보유종목은 매도하지 않았다. 청산 설정 `liquidation_config.json`은 `enabled=false`이며 청산 예약도 설치하지 않았다. `liquidation.py`의 거래 경로는 이 연구·감시 작업에서 실행하지 않는다. 신규 실매수·실매도·환전은 사용자 또는 증권사의 별도 절차에서 수행해야 한다.

## 다음 거래일 준비

2026-09-21 실제 최신 공시 5곳을 비교했으며 4곳은 2026년 2분기 자료를 수집했다. Pershing Square는 요구되는 2분기 원본 13F가 없어 제외했다. 신규 3% 이상 신호는 Coatue의 CBRS, INTC, SPCX였다. 모두 한국투자 종목정보에서 CUSIP과 미국 표준코드를 대조했다.

`tomorrow_plan.py`는 실계좌를 조회해 국내 매도 목록, 미국 후보 수량, 추격 가격 상한과 실행 게이트를 저장한다. 주문 API는 호출하지 않는다.

```sh
.venv/bin/python -m guru_tracker.multi_guru --asof 2026-09-21
.venv/bin/python -m guru_tracker.tomorrow_plan --asof 2026-09-21 --trade-date 2026-09-22
.venv/bin/python -m guru_tracker.preflight --asof 2026-09-21 --trade-date 2026-09-22 --stage morning
.venv/bin/python -m guru_tracker.preflight --asof 2026-09-21 --trade-date 2026-09-22 --stage night
```

첫날 목표는 종목별 계좌 평가액의 20%이며, 최소 5거래일 관찰과 분할·공시 검증이 끝난 뒤 최대 30%까지 별도로 검토한다. 이는 수익을 보장하는 최적 비중이 아니라 최신 후보가 모두 한 운용사와 기술·성장주에 몰린 점을 반영한 출시 제한이다. 밤 프리플라이트가 `READY_FOR_USER_ORDER_ENTRY_AFTER_LIVE_QUOTE_CHECK`가 아니면 주문표를 사용하지 않는다.

`consensus_candidates.csv`에는 여러 구루의 동시 보유 후보를 별도로 저장한다. 각 운용사 포트폴리오에서 1% 이상인 보유만 유효한 선택으로 세며, 3명 이상·중앙 비중 2% 이상이면 `CORE`, 2명 이상이면서 한 명 이상 3% 이상이면 `WATCH`다. 단순 합의 보유는 매수 신호가 아니며 최소 두 구루의 신규 또는 검증된 증액 방향이 확인돼야 추가 검토 단계로 이동한다.

한국투자 계좌는 사용자가 별도로 전체 자산배분을 관리하는 구루 전략 전용 계좌로 취급한다. 현금 목표는 0%이며 1단계는 최신 신규 신호의 공개 비중을 정규화하고 단일 종목 40% 상한을 적용해 SPCX 40%, INTC 31%, CBRS 29%로 배분한다. 다중 구루 방향이 확인된 `CORE` 종목은 즉시 활성 집합에 추가하고, 아직 확인되지 않은 종목의 몫을 포함해 활성 종목끼리 합계 100%로 다시 정규화한다. 모든 CORE 방향이 확인된 2단계 기준 비중은 SPCX 25%, INTC 15%, CBRS 10%, TSM 18%, AMZN 18%, META 14%다. 2026년 2분기 자료에서는 TSM과 META가 `BROAD_ACCUMULATION`, AMZN은 기업행동 검증이 남은 혼합 방향이므로 현재 목표는 SPCX 30.49%, INTC 18.29%, CBRS 12.20%, TSM 21.95%, META 17.07%다. 정수주 단위, 수수료 및 환율 때문에 최저 가격 종목 한 주 미만의 잔액은 남을 수 있고 목표 투자율은 98% 이상이다. 신용·마진 차입과 시장가 주문은 허용하지 않는다.

2026-09-22는 KIS 휴장 조회에서 KRX 개장일로 검증되며, NYSE 공식 달력상 미국 정규장 휴일이 아니다. KRX 오전 주문과 미국 정규장 주문 사이에 매도 체결·통합증거금 주문 가능액을 다시 확인한다. 현재 시세를 내일 지정가로 재사용하지 않는다.

## 환경변수

- 연구·공시 감시: 선택 `SEC_USER_AGENT`.
- 선택 계좌 읽기 전용 조회: `KIS_APP_KEY_LIVE`, `KIS_APP_SECRET_LIVE`, `KIS_ACCOUNT_NO_LIVE`.
- 위 값이 없으면 `KIS_APP_KEY`, `KIS_APP_SECRET`, `KIS_ACCOUNT_NO` 사용. 선택 `KIS_ACCOUNT_PRODUCT` 기본 01.
- 기존 자격증명 파일 경로는 `automation_config.json`의 `credential_file`에서 설정한다. 키 값은 저장소나 대화에 붙여넣지 않는다.
